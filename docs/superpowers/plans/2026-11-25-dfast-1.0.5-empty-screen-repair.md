# DFast 1.0.5 Empty-Screen Repair Implementation Plan

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax for tracking. Execute in order; each task ends with a verifiable result.

**Goal:** Make every screen of DFast show its content after the Flux redesign, and ship the fix as a signed GitHub release that installed 1.0.4 users can update from.

**Architecture:** A single activity (`MainActivity`) hosts all pages in a `FragmentContainerView` (`frame_layout`) inside a `ConstraintLayout`. The Flux redesign moved the bottom navigation into a floating `MaterialCardView` (`dock_card`), which made `dock_card` the only valid sibling to anchor `frame_layout` against. Navigation-visibility code still referenced the bar itself, which now lives inside the card, so the constraint silently failed and the page container measured zero height.

**Tech Stack:** Kotlin, AndroidX Navigation (NavHostFragment), ConstraintLayout, Material 3, GitHub Actions release pipeline.

**Spec:** `docs/superpowers/plans/2026-11-24-dfast-flux-new-identity.md` (the redesign that introduced the regression) and `dfast/CHANGELOG.md` (1.0.4 repair notes).

## Global Constraints

- `applicationId` stays `dfast.app`; packages stay `com.deniscerri.ytdl.*`; GPLv3 attribution is unchanged.
- Allowed external links: `https://github.com/MenuM7D/dfast` and `https://t.me/m7d_devvv` only.
- No local Gradle/JDK: compilation and APK production happen on GitHub Actions only.
- versionCode scheme: `major * 1000000 + minor * 10000 + patch * 100 + build`, then `* 100 + abi` per split.
- The published 1.0.4 (versionCode 1000400) is already installed on devices, so the fix must carry a higher versionCode to be installable as an update.

## Review Focus

- A destination that hides the dock (settings, log detail, queue detail) must give the page full height and bring the dock back on return.
- The keyboard opening must not leave an empty dock card floating above it.
- Rotation to a landscape/tablet layout, where the bar is a `NavigationRailView` sibling, must keep working.
- Cold start on a dock destination must show content with no tap required.
- The release must not leave a broken build as the newest download.

### Task 1: Anchor the page container to the dock card

**Files:**
- Modify: `dfast/app/src/main/java/dfast/app/MainActivity.kt`

**Interfaces:**
- Consumes: `R.id.frame_layout`, `R.id.dock_card`, `R.id.bottomNavigationView`.
- Produces: `MainActivity.showBottomNavigation()`, `MainActivity.hideBottomNavigation()` operating on the dock card; private field `dockView: View?`.

- [x] **Step 1: Record the dock container**

Add `private var dockView: View? = null` and resolve it with `findViewById(R.id.dock_card)` next to the existing `navigationBarView` lookup (null in landscape, where no card exists).

- [x] **Step 2: Anchor pages to a real sibling**

In `showBottomNavigation()`, for the `BottomNavigationView` branch set `bottomToTop = R.id.dock_card` and `bottomToBottom = UNSET`.

- [x] **Step 3: Move the card, not the bar**

Animate/visibility-switch `dockView ?: navigationBarView` in both `showBottomNavigation()` and `hideBottomNavigation()`, so the card never lingers empty.

- [x] **Step 4: Hide the card for the keyboard**

Point the IME inset listener at the dock card: `(dockView ?: this).visibility = ...`.

- [x] **Step 5: Compile on CI** — see Task 3, Step 1.
